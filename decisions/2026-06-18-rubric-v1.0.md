# Relevance rubric locked: v0.1 → v1.0 (after pilot #15)

Date: 2026-06-18

## Decision

Lock the teacher relevance rubric at **v1.0** for the full dispatch (#16),
revised from the pilot disagreements. Core definition of relevance is now
**utility for a correct answer**: *a passage is relevant if a correct written
solution to the question would use it* — judged against a human solution
(model-independent), NOT "what an LLM finds useful".

`src/eval/relevance/build_pairs.py` `RUBRIC_VERSION` bumped to `v1.0`;
`results/relevance_pairs.jsonl` regenerated so dispatch pairs carry v1.0
(content otherwise identical — only the `rubric_version` field changed).

## Pilot evidence (#15)

2 teachers, 80 pairs (5 stratified queries), graded under v0.1
(`experiments/2026-06-18-pilot-annotation/`):

- weighted kappa (0–3) **0.704**, adjacent (|diff|≤1) **96.2%** — broadly aligned,
  no wild disagreement (only 3 pairs off by 2).
- binary-relevant (≥2) kappa **0.587** — the weak spot.
- 32 disagreements, by boundary: **1↔2 = 13** (dominant), 0↔1 = 8, 2↔3 = 8,
  big gaps = 3. Concentrated on property-heavy / multi-step queries
  (`bac2025-e2-1` integral-parity = 8 disagreements; `syn-multi-10` function
  study ≈ 8) where many same-chapter chunks are partially relevant.

Diagnosis: the rubric did not tell teachers how to score "right chapter,
similar-looking, but not the property the question needs."

## What changed in v1.0

1. **Anchor question reframed** to "would a correct solution *use* this passage?"
   + a concrete **"je m'en sers" test** for the 1↔2 boundary (the main fix).
2. **0↔1 sharpened**: a chunk from a *different chapter* that contributes nothing
   = **0**, not 1 (fixes e.g. a variation-table chunk retrieved for a Fermat
   question). **1** is reserved for same-lesson-but-unused.
3. **2↔3 sharpened**: **3** = the exact property/method, sufficient alone;
   **2** = a necessary piece that needs other passages.
4. **Rule added (the judgment call, confirmed by Cedric)**: a *usable stepping
   stone* scores **2 even if a more direct passage exists** — consistent with
   "judge each passage alone" (Rule 5). Resolves the disputed Chasles chunk
   (296-0017): a correct solution *could* use it → 2.
5. **New 4-level worked example** built from the real `bac2025-e2-1` pilot
   cluster (parity property = 3; definition / Chasles = 2; periodicity example
   = 1; rational-fractions = 0).

## Why relevance is anchored to a human solution, not the LLM

Defining relevance by "what the LLM finds useful" would (a) be unjudgeable for
teachers, and (b) contaminate the thesis: it makes the gold model-dependent,
which breaks **H3** (judge-vs-*independent*-human agreement becomes circular)
and **H4** (frontier and SLM "find useful" different things, so a
generator-specific label can't compare them, and you lose the ability to
attribute errors to retrieval vs generation). The "would a correct solution use
it" proxy is model-independent, teacher-judgeable, and still predicts downstream
RAG utility.

## Status of pilot labels

Pilot labels were made under v0.1 → **calibration only, not final gold**. The
pilot queries are re-graded under v1.0 at dispatch. Agreement under v1.0 is
re-measured on the dispatch **anchor** (20 queries × 5 raters) — that is the
real H3 input, not this pilot read.
